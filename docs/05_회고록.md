# AI 코어 프로젝트 2회차 회고록

2026년 10월 22일에 적었다. 아직 안 해본 건 완료했다고 쓰지 않았다.

## 주제를 정하면서

처음엔 화학과 전공을 살려 수용해도를 예측하는 프로젝트를 생각했다. AqSolDB를 찾고 나니 너무 흔한 주제 같기도 하고, 내가 내용을 설명할 수 있을지도 걱정됐다. 요구사항을 다시 보니 이번 과제는 예측 모델보다 RAG 서비스를 만드는 게 중심이었다. 그래서 예측은 보조 기능으로 두고, 데이터와 문헌을 근거로 답하는 쪽에 초점을 옮겼다.

강사님이 RAG는 데이터 싸움이라고 하신 말도 계속 생각났다. 데이터가 많다고 끝나는 게 아니었다. 화합물이 맞는지, 문서 원문이 뭔지, 이용 조건은 어떤지 확인해야 했다. 그래서 자동으로 찾은 자료는 바로 색인하지 않고 사람이 확인한 것만 쓰기로 했다.

## 만들면서

AqSolDB는 9,982행이고, 그중 train 자료에서 100개를 골라 메타데이터 색인에 넣었다. 외부 문서는 현재 아홉 건을 따로 검토해 색인했다. 숫자를 늘리는 것보다 어떤 자료를 썼는지 설명할 수 있는 게 더 중요하다고 생각했다.

실험 LogS와 모델 예측값, 문헌 설명을 한 가지 사실처럼 섞으면 안 된다는 점도 신경 썼다. 예측과 실험값이 다르면 둘 다 보여주고, 문헌이 예측 이유를 증명한다고 쓰지 않도록 했다.

강의 스켈레톤 07의 항목 선택, 진행 상태, 근거 표시 흐름을 앱의 기본으로 삼았다. 08의 위키 API 예제는 문서 검색과 본문을 가져오는 부분을 참고했다. 과제 요구사항 때문에 필요한 검색·색인·대화 기록 코드는 덧붙였지만, 선택 기능인 MMR이나 직접 만든 HTML UI는 넣지 않았다. 앞으로 코드를 더 추가할 때도 스켈레톤이나 체크리스트에 필요한지 먼저 보려고 한다.

## 오늘 확인한 것

앱을 Chrome에서 열어 A-4518과 A-5538을 바꿔가며 검색했다. 화합물을 바꿔도 대화 기록이 서로 섞이지 않았고, 다시 돌아오면 각 기록이 보였다. 분자량과 LogP 조건으로 후보를 찾고 하나를 선택하는 것도 확인했다.

A-4518 보조 분석에서는 예측 LogS와 실험 LogS, 연결된 문헌을 같이 볼 수 있었다. 오늘은 타우린을 한글로 검색해 B-524 카드가 뜨는 것과 의미 검색의 문헌 카드를 브라우저에서 확인했다. 키를 교체한 뒤 GMS 벡터 검색과 답변 생성도 실행해 근거 번호를 대조했다. 답변에 타우린 이름 철자가 틀린 부분이 있어 이름과 수치를 근거대로 옮기라는 지침을 추가했다. 다시 생성한 답변에서는 철자 오류가 재현되지 않았고 인용도 메타데이터와 NOAA 발췌를 가리켰다.

## 남은 일

브라우저에서 타우린 답변의 인용 번호와 문서 링크가 맞는지 확인했다. 키나 색인이 없을 때의 안내와 검색·생성 진행 상태도 이후 실제 브라우저에서 확인했다. 아직 승인하지 않은 외부 문서는 출처와 이용 조건을 확인하기 전까지 색인하지 않는다.

고정 질문 다섯 개로 RAG 전후를 비교했다. 근거를 정확히 가져온 사례도 있지만 부가 설명의 오류도 있어 답변 전체가 항상 정확해졌다고 말할 수는 없다.

- 2026-10-22 브라우저에서 한글 `타우린` 검색 결과·화합물 상세 카드, 벡터 검색 문헌 카드, 생성 답변 화면을 각각 `screenshots/09_taurine_compound.png`, `screenshots/10_taurine_vector_evidence.png`, `screenshots/11_taurine_answer_ui.png`에 저장했다. 답변의 값·단위·온도와 인용된 AqSolDB/NOAA 근거를 대조했다. 앞선 자동화 시도는 동의 체크박스 조작에서 멈췄지만, 이후 키보드 조작으로 답변 생성과 표시까지 확인했다.
- 2026-10-22 AppTest로 키 누락과 빈 문서 색인 상태를 각각 실행했다. 두 경우 모두 사용자 안내가 나타났고 예외는 없었다. 이 확인은 브라우저에서 진행 상태를 살펴본 것과 같지 않으므로, 체크리스트에서는 진행 표시를 미확인으로 두었다.
- 2026-10-22 F2015 비교용 질문 5개와 원문 기준 판정을 먼저 정리했다. 로컬 검색은 각 질문에 대응하는 발췌를 찾았다. GMS 비교 요청은 실행 환경의 DNS 연결 오류로 답변을 받지 못했다. 키 인증 오류가 아니라 요청이 서비스에 도달하기 전 연결 문제라서, 결과를 추측해 채우지 않고 미실행으로 기록했다.
- 2026-10-22 카페인 C-533에서도 이름만이 아니라 문헌 근거가 실제로 필요하다고 판단했다. NOAA CAMEO의 NTP 1992 수용해도 값과 출처 조건을 확인해 한 항목만 승인하고, 출처 표·후보 상태·로컬 JSONL·질문 예시를 맞췄다. 단어 검색은 AppTest에서 값과 원문 링크를 반환했다. 이후 GMS 임베딩과 벡터 검색을 실행해 카페인 근거가 검색되는 것, 생성 답변의 번호·값·단위·온도·원출처가 서로 맞는 것도 확인했다. 색인은 재실행에서 추가 0 / 총 8로 유지됐다.

## 후속 점검 기록

이전 문단의 DNS 실패와 색인 7·8건 기록은 당시 상태다. 이후 네트워크 실행 제한을 해결해 전후 비교를 완료했고, 현재는 아스피린을 포함한 6종의 승인 발췌 9건을 색인했다. 문헌 수용해도의 단위·온도·상한 표현을 그대로 보여주는 비교 기능도 실제 화면에서 확인했다.

중요한 공백도 찾았다. 처음 고른 메타데이터 100개 중 승인 문헌이 있는 항목은 5개뿐이었다. 기존 조사 기록에서 설명 본문과 식별자가 연결된 Train 항목 136개를 확인하고, 문서 확보 대상 100개를 다시 구성했다. 그래도 실제 승인 자료는 6종이고 나머지 94종은 검토 대기다. 자료를 찾았다는 것과 답변에 써도 된다는 것은 다르다는 점을 결과에 남겼다.

제출 구조를 점검하며 승인 CSV가 제외 예정인 research 폴더 안에 있는 문제도 발견했다. 실행에 필요한 승인 자료는 data로 옮기고, 실제 키·색인·research가 없는 별도 복사본에서 앱을 실행해 확인했다. 전체 서비스 완료 판정은 남은 문헌 검토와 별도로 판단해야 한다.

## 화면 재점검과 정리

후속 문헌 검토에서는 인용이 있다는 것만으로 자료를 신뢰할 수 없다는 점을 다시 확인했다. D-1360의 저장 이름은 hydroxy 화합물인데 연결된 CID와 NOAA 자료는 amino 화합물이었다. 어느 필드가 잘못됐는지 확정하지 않은 채 원자료를 고치지는 않았고, 승인 보류 사유로 남겼다. B-1198도 pentene 설명에 Pentane 문서를 인용하고 있어 재확인이 필요하다. 자세한 항목별 판단은 `03_출처_검토_보고서.md`에 기록했다.

추가로 이름을 직접 고를 수 있는 선택창과 공통 질문 예시 36개를 만들었다. 문헌이 준비된 화합물을 먼저 보여 주되 전체 Train 항목도 고를 수 있게 했다. 질문 수를 늘리는 것과 실제 답변 근거를 확보하는 것은 다르므로, 근거 부족을 확인하는 질문도 별도 범주로 두었다.

미검토 후보 94종은 저장된 자료를 기반으로 1차 분류했다. 원출처 인용 없음 59종, 원문·이용 조건 확인 필요 16종, 실질 본문 부족 11종, 범위 밖 설명 8종이었다. 자동 분류를 이용 조건 검토 완료로 바꾸지 않았고 신규 승인도 하지 않았다. 다음 작업은 인용이 있는 16종의 원문을 먼저 확인하고, 부적합한 19종은 물성 설명 자료로 교체하는 것이다.

2026-10-22에는 화면에 남아 있던 이전 Streamlit 실행 프로세스의 `compound_data.refresh_name_links` 오류를 확인했다. 현재 소스와 가상환경을 기준으로 서버를 다시 시작하자 앱이 정상 렌더링됐고, 검색창·화합물 목록·문헌 준비 상태 필터·사이드바 설정이 함께 표시됐다. 오류 화면만 보고 UI가 망가졌다고 판단하지 않고, 실행 프로세스와 현재 코드의 버전을 먼저 대조해야 한다는 교훈을 남긴다.

조건 검색 결과 처리도 빈 결과를 정상적인 상태로 다루도록 정리했다. 기능 모듈은 체크리스트 실행에 사용되므로 삭제하지 않고, `src/README.md`에 화면 핵심 모듈과 검증용 CLI의 역할을 문서화했다. 결과적으로 파일 수를 줄이는 것보다 책임과 제출 제외 범위를 분명히 하는 편이 안전했다.


로컬 검사 명령 `python src/verify_local.py`를 남겨 문서 링크, 전체 화합물 목록, 질문 예시, 수치 검색과 화면 선택 흐름을 다시 확인할 수 있게 했다. 4개 검사를 통과했고, UI 검사 중 LLM·임베딩 클라이언트를 차단해 불필요한 모델 호출을 방지했다. 다만 자동 UI 검사를 실제 브라우저의 시각 점검이나 답변 품질 평가로 표현하지 않았다. 문헌 94종 검토와 동료 상호 점검은 여전히 남아 있다.
