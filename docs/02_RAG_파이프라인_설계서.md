# RAG 파이프라인 설계서

## 전체 흐름

준비 단계: AqSolDB Train → 메타데이터 텍스트 → 메타데이터 컬렉션. 별도로 검색어 추출 → 외부 후보 수집·선별 → 식별자·원출처·이용 조건 검토 → 승인 발췌 청킹 → 문헌 컬렉션을 구성한다.

질의 단계: 화합물 선택 → 메타데이터 고정 포함 + 같은 화합물의 문헌 검색 → 중복 제거·근거 번호 부여 → LangGraph `retrieve → generate` → 답변과 실제 인용된 근거 표시.

## 두 컬렉션과 메타데이터

| 컬렉션 | 현재 범위 | 주요 필드·ID |
|---|---|---|
| `aqsoldb_compounds_linked` | Train 100건, 항목당 1텍스트 | ID·이름·별칭·InChIKey·SMILES·LogS·descriptor·원자료 코드·DOI·문서 후보 URL·검토 상태. 고정 ID는 화합물 ID |
| `aqsoldb_documents` | 승인 6종·9발췌 | 문서 ID·청크 번호·화합물 ID·InChIKey·제목·발췌·원문 URL·원출처·이용 조건·검토 범위. ID는 `compound_id:document_id:sequence` |

화합물 정보와 외부 설명을 별도 관리해 실험 기록을 문헌 설명으로 혼동하지 않게 한다. 메타데이터는 항목 전체를 한 문서로 유지하고 문헌만 청킹한다. 기존 ID를 확인해 재실행 시 중복 추가를 막는다. Test 분할은 색인하지 않는다.

## 수집·선별·승인

1. `src/index_metadata.py`가 `data/document_discovery_manifest.csv`의 Train 100종을 읽고 검색용 텍스트를 만든다.
2. `src/discover_wikipedia_candidates.py`가 선택 항목과 질문에서 검색어를 추출한다. 직접 화합물 검색어를 코드에서 보강한다.
3. PubChem 또는 Wikimedia API로 후보를 모으고 LLM이 제목·요약을 바탕으로 포함/제외 ID와 이유를 정한다. 직접 화합물 문서는 우선 포함한다.
4. 원문 식별자·인용·이용 조건을 검토한 발췌만 `data/approved_external_sources.csv`의 승인 대상으로 옮긴다. LLM 선별은 재사용 승인이 아니다.
5. `src/index_external_documents.py`가 승인 JSONL을 만들고, `--index`일 때만 청킹·임베딩한다. 캐시는 화합물·질문·제공자를 구분하며 반복 수집을 생략한다.

Wikimedia 신규 수집은 운영자 연락처가 없으면 요청 전에 차단한다. PubChem 단독 경로는 `--provider pubchem`이다. 외부 요청의 간격·재시도 정책은 [검증 결과](06_검증_결과.md)와 증거 JSON에 기록했다.

## 프롬프트 3종

| 프롬프트 | 입력·역할 | 출력 형식 |
|---|---|---|
| 검색어 추출 | 화학 정보 검색 역할. 선택 화합물의 이름·구조·식별자와 질문에서 검색 표현 생성 | JSON 문자열 배열. 직접 화합물 검색어를 보강하고 최대 5개로 제한 |
| 후보 선별 | 화합물과 후보의 제목·요약·URL을 비교해 포함·제외 판단 | `{"include":[{"id":"...","reason":"..."}],"exclude":[{"id":"...","reason":"..."}]}` |
| 근거 기반 답변 | 선택 항목과 제공된 근거만 사용. 값·단위·온도를 보존하고 없으면 보류 | 답변 텍스트. 주요 주장에 `[근거 N]` 인용 |

검색어·선별 JSON 형식을 검증한다. 생성 답변에서 제공하지 않은 근거 번호가 나오면 답변을 보류하고 빈 인용 목록을 반환한다. 전체 프롬프트는 화면에 표시하지 않는다.

## 검색·병합·인용

- 선택 화합물 메타데이터는 순위와 관계없이 근거 1로 포함한다.
- 의미 검색은 문헌 컬렉션에서 선택 화합물 ID로 범위를 제한하고 질문 임베딩으로 검색한다. UI 기본값은 Top-k 3이며 1~10으로 조절한다. CLI·공통 설정 기본값은 6이다.
- UI 기본인 단어 일치 검색은 일부 한글 용어 확장을 적용하는 무료 로컬 경로다. 의미 검색과 동일한 검색 방식으로 설명하지 않는다.
- 두 결과를 청크 ID로 중복 제거하고 외부 자료에 근거 번호를 부여한다.
- `rag_graph.py`의 `retrieve`와 `generate` 두 노드를 연결한다. 질문이 레코드에도 없고 외부 근거도 없으면 생성 API를 호출하지 않고 확인 불가로 안내한다.
- 답변의 `[근거 N]`을 추출해 실제 인용된 자료만 제목·유형·원출처·URL과 함께 표시한다. 인용이 없으면 별도로 안내한다.
- 대화 이력은 Streamlit 세션에서 화합물 ID별로 나눠 저장한다.

## 설정값을 선택한 이유와 비교 결과

| 설정 | 선택 이유 | 실행 비교 |
|---|---|---|
| 문헌 1,000자·중복 200자 | 짧은 승인 발췌와 조건·출처의 문맥을 보존하는 시작값 | 승인 문서 3건에서 1,000/200은 3청크, 150/30은 7청크. 격리 컬렉션으로 비교 |
| UI Top-k 3 | 현재 화합물별 발췌가 적어 과도한 근거 나열을 줄임 | A-4518 동일 질문에서 k=1은 1건, k=3은 2건 |
| 2개 컬렉션 | 항목 기록과 문헌 본문을 분리하고 각 출처 유형을 표시 | 메타데이터 100건·문헌 9건, 재실행 신규 0건 |

작은 발췌 집합에서 얻은 비교이며 검색 최적값을 일반화하지 않는다. 설정과 실제 검증은 [체크리스트](../체크리스트.pdf)에 연결했다.

## 도메인 기능과 UI

문헌 수용해도 값과 AqSolDB LogS를 단위·온도·원출처별로 나눠 비교한다. 숫자가 다르다는 이유만으로 오류라고 단정하지 않으며 조건이 없으면 직접 비교를 보류한다. 검색된 발췌와 원문 링크를 함께 보여줘 F2010의 근거 사용을 충족하도록 설계했다.

LogS 회귀·유사 descriptor 화합물은 보조 분석이다. 예측과 실험값을 구분하고 문헌이 모델의 인과 설명이나 정확성을 증명한다고 표현하지 않는다. 새 SMILES는 RDKit으로 구조·descriptor를 계산한다.

키·색인 없음, 검색·생성 중, 오류 상태를 따로 안내한다. 의미 검색과 생성은 각각 동의 후 실행한다. API 키·전체 프롬프트·traceback은 화면에 표시하지 않는다.

## 문제와 해결

| 문제 | 해결·제한 |
|---|---|
| 후보 문서와 승인 근거가 혼동됨 | 후보 목록·승인 CSV·색인을 분리. 94종은 계속 검토 대기 |
| 복합제 이름의 부분 일치로 직접 문서 오인 | 화합물 이름 매칭 규칙 보완. 정체성 충돌 후보는 승인 보류 |
| LogS와 문헌 온도·단위 혼동 | 메타데이터와 생성 지침 보완 후 카페인 질문 재검증. 최초 오류 기록도 유지 |
| 파일이 있어도 실행 프로세스가 이전 코드를 사용 | 현재 가상환경으로 재실행 후 화면 확인 |
| 첫 화면 설명이 길고 값의 해석이 어려움 | 범위 설명을 접는 영역으로 이동하고 실험값·예측값 옆에 참고 눈금 추가 |
