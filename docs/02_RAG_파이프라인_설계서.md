# 분자 수용해도 예측 및 근거 탐색 — RAG 파이프라인 설계 초안

> 상태: 초안. 과제 요구사항 번호별 문구와 최종 데이터 출처 목록을 대조한 뒤 확정한다. 외부 설명 문서의 원출처·이용 조건이 확인되지 않은 자료는 색인 확정 목록에서 보류한다.

## 1. 목표와 범위

사용자가 AqSolDB의 화합물을 선택하고 질문하면, 화합물 메타데이터와 출처를 확인한 외부 설명 문서를 각각 검색해 관련 근거를 보여준다. 생성 답변은 검색 결과에 근거한 쉬운 설명이며, 검색 문서에 없는 사실을 추측해서 채우지 않는다.

회귀 모델은 별도 기능으로 `Y`(실험 LogS)를 예측한다. RAG는 용해도에 관한 설명 문서의 질의응답을 담당하고, 모델의 예측값을 출처 문서의 사실처럼 표현하지 않는다.

## 2. 데이터 컬렉션

### 화합물 메타데이터 컬렉션 (F2001-F2002)

- 로컬에는 train/test 9,982개가 있다. 현재 임베딩 컬렉션은 test 분할을 건드리지 않고 train에서 뽑은 100개 출처 균형 샘플만 색인한다. F2001 최소 100건을 넘기면서 GMS 사용량을 제한하는 선택이다. 표본에는 세 승인 문서의 대상과 아스피린·카페인을 반드시 포함한다.
- 최소 필드: `ID`, `Name`, `InChIKey`, `SMILES`, `Y`, 사용 가능한 descriptor, `Group`, AqSolDB ID 원자료 코드(A-I), canonical DOI
- 한 화합물 행을 핵심 이름·별칭·SMILES·LogS 해석·주요 descriptor를 포함한 검색용 단일 텍스트로 만들고, 전체 descriptor는 Chroma metadata에 보존하며 고정 `chunk_id=ID`로 저장한다. 재실행 시 기존 ID를 건너뛰고 로드/색인 건수를 표시한다.
- 검색/필터: 이름, ID, InChIKey 검색; `Y`·분자량 등 숫자 조건은 허용 필드와 범위를 검증한 뒤 적용
- 각 레코드는 `train.csv`/`test.csv` 출처와 원자료 행 ID를 보존한다. 예측 대상 `Y`나 시험 데이터 값은 문서 생성형 답변의 근거 문장으로 꾸며내지 않는다.

### 외부 문서 컬렉션 (F2004-F2005)

- 최소 필드: 문서 ID, 연결된 AqSolDB ID 또는 InChIKey, 제목, 본문/청크, 문서 제공자, 원문 URL, PubChem CID(해당 시), 원출처 인용, 수집일, 이용 조건 상태, 원문 해시/버전
- 선택 화합물 자체를 다루는 문서는 관련성 선별 및 일반 길이 제외 규칙보다 우선하여 포함한다.
- 원출처 인용이 표시되지 않거나 이용 조건을 확인하지 못한 후보는 `pending` 상태로 관리한다. 과제 제출용 확정 색인에는 승인된 문서만 넣는다.
- 화합물 메타데이터와 외부 문서는 서로 다른 두 컬렉션에 둔다. F2016을 선택하면 제3 출처 유형/컬렉션 추가 여부를 확정한다.

## 3. 수집 및 색인 절차

1. AqSolDB 행을 `ID`·`InChIKey`로 정규화하고 원자료 출처 코드 A-I를 붙인다. 검색어 추출 프롬프트는 JSON 배열로 파싱하며, 선택 화합물 자체의 이름/식별자 검색어를 항상 포함한다.
2. 공식 API/공개 문서에서 화합물별 외부 문서 후보를 가져온다. 후보 선별 프롬프트로 포함/제외와 이유를 남긴다. 수집 실패, CID 미매칭, 본문 없음, 출처 누락은 오류/보류 상태로 기록한다.
3. 원문 URL, 제공자, 원출처 인용, 이용 조건, 수집 시각을 검토한다. 검토가 끝나지 않은 항목은 별도 격리한다.
4. 승인 문서에서 제목과 본문을 설정 가능한 청크 크기/중복 길이로 나눈다. 청크 ID는 `화합물 ID:문서 ID:순번`을 포함하고 문서 ID, URL, 인용 정보를 붙인다.
5. 성공 처리한 검색어와 문서 URL/본문 해시를 캐시한다. 색인 갱신 때 중복 URL/본문 해시를 확인하고 처리·실패·보류 건수를 로그로 남긴다.

## 4. 질의 처리

1. 사용자가 화합물을 선택하고 질문을 입력한다. 선택 항목의 ID·InChIKey를 기준으로 검색 범위를 묶는다.
2. 화합물 메타데이터 청크는 검색 순위와 무관하게 항상 근거에 포함한다. 외부 문서는 선택 화합물 범위에서 질문 임베딩과의 의미 유사도로 검색하고 Top-k는 설정으로 바꾼다.
3. 두 컬렉션 결과를 청크 ID로 병합·중복 제거한다. 관련 외부 근거가 없으면 그 사실을 표시하고 무근거 답변을 생성하지 않는다.
4. LangGraph는 `retrieve`와 `generate` 두 노드로 구성한다. LLM에는 질문, 선택 화합물, 검색 근거, 출처 메타데이터만 전달한다. 답변의 실제 사용 근거에 `[근거 N]` 번호를 붙이고 화면에는 인용된 근거만 제목·유형·제공자·URL과 함께 표시한다.
5. 수치 예측은 별도 회귀 경로를 호출해 “모델 예측”과 실험 데이터 `Y`를 구분한다. 데이터셋 DOI 및 사용된 실험 행 ID를 근거로 표시한다.

## 5. 답변 정책

- 검색 근거에 없는 값, 기전, 안전성, 실험 절차를 단정하지 않는다.
- 서로 다른 출처가 다르면 각 출처의 주장과 연도를 나눠 보여준다.
- 화합물 구조 매칭이 모호하거나 유사 화합물뿐이면 직접 일치 문서가 아님을 표시한다.
- 문서 설명은 과학적 사실 요약으로 제한하고 건강·안전 판단이나 실험 취급 안내는 제공 범위에서 제외한다.
- 문서가 없거나 검색 품질이 낮으면 추측 답변 대신 검색 실패/문서 미확보 메시지를 보여준다.

## 6. 프롬프트 3종 설계

1. **검색어 추출:** 화학 정보 전문가 역할을 주고 선택 화합물의 이름·SMILES·InChIKey와 사용자 질문에서 검색어를 뽑는다. JSON 문자열 배열만 출력하게 하고, 선택 화합물 자체를 찾는 검색어를 코드에서 추가해 누락을 방지한다.
2. **후보 문서 선별:** 제목·요약·URL·화합물 매칭 정보를 입력해 포함/제외 ID와 짧은 사유를 JSON으로 출력한다. 선택 화합물 자체의 문서가 후보에 있으면 우선 포함한다. 최종 문서 원문과 출처/이용 조건은 LLM 판단과 별도로 검토한다.
3. **근거 기반 답변:** 질문과 근거 청크만 제공한다. 각 주요 주장에 `[근거 N]` 표기를 요구하고, 근거로 알 수 없으면 확인 불가로 답하게 한다. 출처 번호는 실제로 답변에 인용된 항목만 UI에 보여준다.

## 7. UI 상태와 오류 처리

- 상태: 초기화 중, 데이터 로딩 중, 문서 검색 중, 답변 생성 중, 완료, 일부 자료 누락, 오류
- 선택 화합물 없음: 검색/질문 실행을 안내한다.
- API 제한/네트워크 오류: 재시도 가능 여부와 실패 단계를 표시하고, 미수집 자료를 성공으로 간주하지 않는다.
- 외부 문서 없음: 화합물 데이터만 표시하고 RAG 답변을 생성하지 않는다.
- 외부 문서 근거가 없고 질문이 선택 레코드의 명시적 메타데이터(LogS·원자료 그룹·DOI·구조 식별자 등)에도 해당하지 않으면 모델 API를 호출하지 않고 답변을 보류한다. 메타데이터에 관한 질문은 해당 메타데이터 근거만으로 답한다.
- 출처 표시는 답변 본문과 분리된 링크 목록으로 제공해 사용자가 원문으로 이동할 수 있게 한다.

## 8. 구현 후보와 보류 결정

- 현재 확정: AqSolDB 공개 v1 데이터 메타데이터의 CC0 1.0 표시 및 DOI 인용, 화합물 ID의 A-I 원자료 코드 보존.
- 보류: PubChem Record Description 후보의 원출처와 annotation별 이용 조건 확인. 후보 CSV의 PubChem URL만으로 문장 재사용 승인을 뜻하지 않는다.

## 9. 데이터 품질 우선순위

- 후보 문서 목록과 승인된 색인 입력을 분리한다. 승인 입력은 `research/provenance/approved_external_sources.csv`의 `index_eligible=yes` 행으로만 제한한다.
- 각 문서는 AqSolDB ID·InChIKey·PubChem CID·공식 문서의 CAS/이름을 교차 확인한다. PubChem CID 단독 일치는 구조 이성질체 혼동을 배제하지 못하므로 원문 식별자도 확인한다.
- 문장마다 원출처 attribution, 문서 URL, 출처 조건 근거 URL, 검토일, 색인 허용 범위 및 제외 범위를 함께 보존한다.
- 측정 조건(단위·온도)이 있는 물성값은 원형 그대로 전달한다. AqSolDB의 logS와 등가라고 처리하려면 측정 방법·단위 변환·조건을 별도로 확인한다.
- `src/external_documents.py`는 선택된 세 AqSolDB ID와 InChIKey를 로컬 표본과 대조하고, 승인된 발췌만 외부 문서 레코드로 만든다. `src/index_external_documents.py` 기본 실행은 `data/curated_external_documents.jsonl`을 생성하며 네트워크를 호출하지 않는다. 실제 임베딩/Chroma 적재는 `--index`를 명시한 경우에만 실행하도록 분리했다. 색인 시 `CHUNK_SIZE`/`CHUNK_OVERLAP`을 적용하고 `compound_id:document_id:sequence` ID를 부여한다.
- `src/discover_wikipedia_candidates.py`는 선택 화합물과 질문에서 GMS JSON 검색어를 추출하고 Wikipedia 검색 및 PubChem PUG-REST/PUG-View 용해도 주석을 후보로 가져온 뒤 GMS JSON 선별을 기록한다. 성공한 화합물/질문 검색은 `research/provenance/external_document_search_cache.jsonl`에 검색어·후보 ID·선별 결정을 캐시한다. 반복 실행은 캐시를 사용하고 `--refresh`로만 재수집한다. 후보에는 원문 URL·발췌·언어/주석·화합물 ID·InChIKey·원출처 인용·제공된 이용 조건 메모를 보존한다. 기본으로 색인하지 않으며 사람이 원문 식별, 출처 attribution과 페이지/기여자별 이용 조건을 확인한 뒤에만 승인 자료로 옮긴다.
- E-1274에서 후보 흐름을 실행해 이번 실행에서 신규 후보 10건을 저장했고, 이 가운데 PubChem 용해도 주석 6건은 전부 선별 후보에 포함됐다. 이 실행은 검색·선별의 정상 동작을 확인한 것이며 외부 출처의 유효성 승인이나 RAG 색인을 의미하지 않는다. PubChem 후보별 라이선스 메모가 다르므로 사람이 검토해야 한다.
- 승인된 세 개의 좁은 발췌는 JSONL과 `indexes/aqsoldb_documents` Chroma 컬렉션에 색인했다(초기 실행: 기존 0, 추가 3, 총 3 청크). 문서별 청크 크기·중복 설정 비교와 검색 결과 확인은 아직 필요하다.
- 메타데이터 컬렉션은 `indexes/aqsoldb_compounds`에 train 출처 균형 표본 100건으로 색인했다. 재실행은 기존 100 / 신규 0 / 총 100으로 멱등성을 확인했다. 색인 단계에서 평가용 test.csv는 임베딩하지 않는다.

### 로컬 검색 프로토타입

- `src/retrieve_local_evidence.py`는 사용자가 선택한 AqSolDB ID를 정확히 조회하고, 메타데이터와 검토된 외부 근거를 서로 다른 결과 필드로 반환한다.
- 외부 근거는 같은 AqSolDB ID에 연결된 승인 자료만 대상으로 하며, 질문 단어와 발췌문 단어가 겹치는 자료만 반환한다. 현재 검색은 결정적 단어 일치와 일부 한국어 용어 확장으로 제한되며 의미 기반 검색이 아니다.
- 반환 JSON에는 데이터셋 DOI/원자료 코드와 외부 문서의 attribution·원문 URL·검토 범위를 포함한다. 이 모듈은 검색 결과만 만들고 답변을 생성하지 않는다.
- 확인 명령: `python src/retrieve_local_evidence.py A-4518 "물에 대한 용해도"`. 이 실행에서 A-4518의 메타데이터와 CAMEO CH8856의 검토 발췌가 따로 반환됨을 확인했다. 네트워크나 임베딩 API는 호출하지 않았다.

### LangGraph 및 시연 UI 초안

- `src/rag_graph.py`는 `retrieve` → `generate` 두 노드로 구성한다. 검색은 기본 로컬 모드이며, vector 모드를 선택한 코드 경로는 외부 문서 컬렉션에서 선택 ID 필터와 Top-k를 적용한다.
- 생성 노드는 검색 근거만 프롬프트에 넣고 메타데이터와 외부 자료의 성격을 구분하도록 지시한다. 반환된 답변의 `[근거 N]` 표기를 추출해 UI가 실제 인용된 자료를 가릴 수 있게 한다.
- `app.py`는 선택된 세 화합물의 실험값·구조·로컬 근거를 표시하고 대화 기록을 ID별로 나눈다. 답변 생성을 위해 사용자가 비용 안내 체크박스와 버튼을 직접 선택해야 한다.
- A-4518의 측정 조건 질문 한 건을 GMS로 실행했다. LogS와 외부 문헌의 단위·온도를 구분하고, `[근거 1]`, `[근거 2]`를 실제 제공 근거와 일치하게 반환했다. 외부 근거가 없는 pKa 질문은 모델 호출 없이 보류하는 동작을 로컬 경로에서 확인했다. 브라우저 UI의 인용 목록 표시와 키 누락 안내는 후속 확인 대상이다.

### 자연어 조건 검색 초안

- `src/filter_compounds.py`는 미리 선언한 별칭과 숫자 경계/범위 문법만 받아 구조화된 조건으로 바꾼 다음, `train.csv` 행에 실제 수치 비교를 적용한다. 파싱되지 않은 필드나 연산자는 후보 결과를 만들지 않는다.
- `app.py`는 일치 건수와 결과 일부를 표시하고, 선택한 AqSolDB ID로 화면 화합물을 전환한다. 검색은 train 데이터에만 적용해 제공 test 분할을 미리 소비하지 않는다.
- 제한된 문법이라 자유 형식 자연어 전체를 이해하지 못하며, 브라우저 실행과 사용자 입력 범위 검증이 남아 있다.
- 선택한 구현 기반: UI 예제에서 사용한 LangGraph/Chroma/Streamlit 구조를 참조한다. 현재 메타데이터 인덱서의 외부 임베딩 모델과 설정값은 `.env`로 바꿀 수 있다.
- 초기 설정 후보: 외부 문서 1,000자 청크, 200자 중복, 외부 Top-k=6. 이는 시작값이며 체크리스트 실행에서 설정을 바꿔 차이를 확인하고 최종값을 기록한다.
- Streamlit 세션 상태의 대화 기록은 화합물 ID별 딕셔너리로 분리한다. UI 화면에서는 수집/검색/생성 진행 상태, 색인 없음, 키 누락을 각각 안내한다.
- API 키는 코드나 로그에 기록하지 않고 로컬 `.env`에서 읽는다. `.env.example`에는 변수명만 둔다.

## 10. 검증 계획 (구현 후)

- 근거 있는 답변에 원문 URL과 문서 메타데이터가 표시되는지
- 근거 없는 질문에서 무근거 생성 대신 보류하는지
- 잘못된/미선택 화합물 ID, 검색 0건, API 오류, 부분 실패가 구분되는지
- train/test 및 외부 문서 출처 필드가 보존되는지
- 출처 인용이 답변에서 원문 청크까지 역추적되는지
- 과제 체크리스트의 F2001-F2012 각 항목과 이 문서의 설계/구현/증거가 연결되는지
