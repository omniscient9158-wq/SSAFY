# 검증 결과

기초 데이터·모델·RAG 평가를 통합했다. 각 실험의 시점과 한계는 아래 기록을 따른다.

## AqSolDB 기초 데이터 점검

## 확인 범위

`data/train.csv`와 `data/test.csv`를 읽어 행 수, 결측치, LogS(`Y`) 분포, 그룹 분포, ID/InChIKey 중복 및 분할 간 구조 식별자 겹침을 살폈다. 이 점검은 모델 성능 평가가 아니다.

## 데이터 개요

| 항목 | Train | Test |
|---|---:|---:|
| 행 수 | 7,488 | 2,494 |
| 열 수 | 29 | 29 |
| `Y` 평균 | -2.883 | -2.910 |
| `Y` 표준편차 | 2.372 | 2.356 |
| `Y` 범위 | -13.172 ~ 2.138 | -12.950 ~ 1.908 |
| `Y` 중앙값 | -2.542 | -2.824 |
| 결측 셀 | 0 | 0 |
| 중복 ID | 0 | 0 |
| 중복 InChIKey | 0 | 0 |

`train.csv`에는 source code A-F, `test.csv`에는 A-I가 들어 있다. 두 분할은 `ID`와 `InChIKey`가 겹치지 않는다. 다만 정확히 같은 SMILES 문자열이 27종 확인되어, 분할은 InChIKey 기준으로 나뉜 것으로 보인다. AqSolDB의 일부 염·무기물 행은 SMILES가 핵심 이온/부분 구조만 표현하는 사례가 있어, SMILES만으로 중복 여부를 판단하지 않는다. 모델링 전 RDKit으로 구조를 파싱하고 표준화한 뒤 중복/염 처리 정책을 정해야 한다.

불균형한 범주 분포이므로 전체 성능 하나만 보고 품질을 판단하기 어렵다. 이후 평가에서는 `Group`별 오차도 함께 비교한다. 그룹 의미는 AqSolDB 논문 정의를 확인한 뒤 README/화면에서 설명한다.

## 모델링 전 결정할 점

1. `Y`가 예측 대상이며, descriptor만 입력으로 쓰고 `Y`, `ID`, `Name`, `InChIKey`, `SMILES`, 측정 관련 `SD`/`Ocurrences`를 입력 변수로 섞지 않는다.
2. 제공된 train/test 분할을 유지하고, train 내부 검증으로 모델 선택을 한다.
3. MAE/RMSE를 중심으로 기록하고, `Group`별 오차를 함께 확인한다.
4. `Group`은 데이터 신뢰도/출처 구성과 관련된 그룹이므로 그룹별 편향을 살핀다. 단, 정확한 범주 정의는 원논문을 근거로 적는다.
5. SMILES 파싱·염/다성분 화합물 처리는 RDKit 도입 여부를 확인한 다음 별도로 정한다.

## 출처 및 한계

- 실험값과 feature 데이터: Harvard Dataverse AqSolDB, DOI https://doi.org/10.7910/DVN/OVHAW8 (공식 Dataverse v1 메타데이터의 CC0 1.0 표기 확인).
- 행 ID의 A-I 코드는 논문 Table 1 및 데이터셋 설명을 통해 원자료 묶음에 연결한다. Dataverse CC0는 배포된 AqSolDB 데이터셋에 대한 표시이며, upstream 원자료의 별도 라이선스까지 모두 CC0라고 뜻하지 않는다.
- 로컬 train/test 파일은 Hugging Face 분할 사본이다. 재현을 위해 미러 URL과 canonical DOI를 함께 기록한다.
- 분포 요약만으로 분자 descriptor와 용해도 사이의 인과관계를 결론내리지 않는다.

## AqSolDB descriptor 회귀 기준선 — 초기 결과

## 실험 설정

- 입력: `train.csv`의 17개 수치 분자 descriptor
- 타깃: 실험 수용해도 `Y`
- 분할: train 안에서 `Group` 비율을 대략 유지해 80:20 검증 분할, random seed 42
- 모델: 표준화 후 Ridge 회귀(alpha=1.0)
- 비교 기준: 훈련 부분의 `Y` 평균만 예측
- 금지한 입력: `Y` 외 정답/측정 관련 값, 식별자/이름/SMILES, Group
- 제공된 `test.csv`는 이번 기준선 적합 및 튜닝에 사용하지 않았다.

## 결과

| 검증 결과 | MAE | RMSE | R² |
|---|---:|---:|---:|
| Train 평균 예측 | 1.902 | 2.366 | -0.001 |
| Ridge 기준선 | 1.146 | 1.508 | 0.593 |

단위는 원본 `Y`의 LogS 단위다. 한 번의 내부 무작위 분할에서 선형 Ridge 모델이 평균 예측보다 낮은 오차를 보였다. 아직 하이퍼파라미터 탐색, 반복 교차검증, 구조 기반 분할, 최종 test 평가를 하지 않았으므로 일반화 성능이나 최종 모델 성능으로 해석하면 안 된다.

## 재현

프로젝트 루트에서 `python src/baseline_solubility.py`를 실행한다. 스크립트는 `data/train.csv` 내부에서만 검증 분할을 만든다.

## 다음 단계

1. Ridge alpha를 검증 분할에서만 선택하거나 교차검증으로 비교한다.
2. 데이터 원논문에서 `Group` 의미를 확인한다.
3. 분자 구조 기반 분할의 필요성과 AqSolDB source/group 편향을 검토한다.
4. 선택한 모델/설정이 고정된 뒤에만 제공된 test split을 최종 1회 평가에 사용한다.
5. RAG 문서 출처 검증과 앱 구현은 별도 트랙으로 이어간다.

추가 평가: 무작위 분할 결과만으로는 원자료 출처가 달라질 때의 일반화를 알 수 없어, train 내부에서 A-F 원자료 그룹을 하나씩 holdout한 분석을 별도로 수행했다. 결과와 한계는 [출처별 일반화 분석](06_검증_결과.md)에 기록했다.

## 원자료 그룹을 나눠 본 LogS 예측 — 초기 분석

## 질문

분자 descriptor로 LogS를 예측할 때, 훈련에 없던 원자료 그룹의 화합물에도 성능이 유지되는가? 이 분석은 예측 성능의 차이를 살펴보며, 출처 그룹이 오차를 일으킨다는 인과관계를 증명하지 않는다.

## 방법

- 사용 데이터: `data/train.csv`만 사용. 제공된 `test.csv`는 열지 않았다.
- 분할: `ID` 접두어 A-F 중 한 원자료 그룹을 통째로 검증에 두는 leave-one-source-code-out 방식.
- 입력: Ridge 회귀, descriptor 17개, alpha=1.0. 각 fold의 평균과 표준편차는 해당 fold의 학습 부분에서만 계산했다.
- 비교 기준: 각 검증 fold의 학습 부분 `Y` 평균을 예측.
- 보고 지표: MAE, RMSE, R². 검증 표본 수가 작은 그룹의 R²는 특히 불안정할 수 있다.

## 해석과 한계

- 여섯 출처 그룹을 합친 결과에서 Ridge의 MAE는 fold별 학습 평균 기준선보다 낮았다.
- 출처별 오차는 같지 않았다. A 그룹을 제외한 fold에서는 R²가 음수였고, 다른 그룹에서는 양수였다. 이는 해당 그룹 밖의 자료로 학습한 경우를 한 번의 모델 설정에서 관찰한 결과다. 데이터 분포·측정 조건·전처리·그룹 크기 등 여러 설명이 가능하므로 출처 자체의 인과 효과로 말할 수 없다.
- 이 분할은 원자료 그룹 단위라 무작위 분할보다 엄격한 일반화 점검이지만, 유일한 평가 방법은 아니다. random split 결과와 나란히 보고해야 하고, 향후 scaffold split도 고려한다.
- 그룹별 결과는 표본 크기와 `Y` 분포의 영향을 받는다. 특히 작은 검증 그룹 R²를 순위처럼 해석하지 않는다.
- 이 초기 분석으로 alpha를 선택하거나 모델을 튜닝하지 않았다. 전체 제공 test는 최종 평가까지 보류한다.

## RAG 적용 전후 답변 비교 기록

## 목적과 방법

같은 GMS 모델에 같은 질문을 보내되, 기준 답변은 검색 근거 없이 생성하고 RAG 답변은 AqSolDB 메타데이터와 승인된 문헌을 검색해 생성한다. 답변 정확성, 원문 인용 일치, 근거에 없는 내용의 보류 여부를 질문별로 기록한다. 이 비교는 작은 사례 점검이며 모델의 일반 성능을 측정하는 실험은 아니다.

2026-10-22 전임 대화의 로컬 검색 기반 5문항 비교 출력을 복구했고, 현재 작업 경로에서 의미 검색 기반 비교도 실행했다. 모델은 `gpt-5.4-nano`, 의미 검색 Top-k는 3이다. 일반 실행의 DNS 실패는 네트워크 권한을 적용한 실행에서 해소됐다. 공개 질문·레코드·승인 발췌의 GMS 전송은 사용자의 명시적 승인을 받고 진행했다.

## 결과 기록

| 번호 | 검색 근거 | 검색 없는 답변 | RAG 답변·인용 | 판정 |
|---:|---|---|---|---|

| 2 | Wikipedia 타우린 구조 발췌 | 발췌 부재를 밝히면서 SO3H를 황산기라고 잘못 표현 | 양쪽성 이온과 `H3N+–CH2–CH2–SO3−`를 `[근거 2]`로 인용 | 구조 표기 일치. Wikipedia 출처명은 답변 본문에서 생략, 근거 카드/원본 JSON에 보존 |
| 3 | NOAA/USCG 외관 발췌 | 원문을 볼 수 없다고 보류 | `White to yellow solid with a weak aromatic odor`와 `Sinks in water`를 `[근거 2]`로 인용 | 발췌 일치. 거동을 정량 용해도로 바꾸지 않음 |
| 4 | NOAA/NTP 카페인 발췌 | 문헌 기록을 특정할 수 없다고 보류 | `10 to 50 mg/mL`, `73°F`, NTP 1992를 `[근거 2]`로 인용 | 핵심 기록 일치. 부가 설명의 “온도/단위가 LogS 자체로 제공됨”은 부정확하므로 답변 전체를 정확하다고 판정하지 않음 |
| 5 | 타우린 관련 3개 발췌, pH별 정량값 없음 | 근거가 없어 정량값을 보류 | pH별 수치가 없다는 점을 메타데이터·수용해도·일반 배경과 구분해 인용 | 정량값을 만들지 않음. 이번 사례에서는 양쪽 모두 보류 |

모든 RAG 인용 ID가 실제 제공된 근거에 속하고 화합물 ID가 일치했다. 이는 문장 전체의 정확성을 보장하지 않는다. 위 판정은 승인 발췌 및 로컬 AqSolDB 레코드와 대조한 결과이며 원문 사이트를 이번에 다시 수집한 결과는 아니다.

원본 답변과 제공 근거는 [의미 검색 비교 JSON](evidence/rag_comparison_vector_20261022.json)에 저장했다. 전임자의 [로컬 검색 비교 JSON](evidence/rag_comparison_recovered.json)은 대화 도구 출력을 복구한 자료이며, 이번 실행 결과와 합치지 않았다. 전임 기록에서는 안트라센 기준 답변이 원문과 다른 외관을 추정했지만 이번 기준 답변은 보류했다. 한 번의 결과를 일반화할 수 없음을 보여준다.

## 재현 실행 (2026-10-22 인계 후 작업)

카페인 부가 설명 오류를 수정하기 위해 검색 메타데이터에 LogS 정의와 온도·pH 미기재 상태를 추가하고 생성 지침을 보완했다. 동일 카페인 질문을 GMS로 1회 재검증했으며, 새 답변은 LogS -0.91의 정의·레코드 온도 미기재·외부 문헌의 73°F를 분리했다. [수정 후 실행 기록](evidence/caffeine_logs_clarification_20261022.json)에 답변과 제공 근거를 보존했다. 위 5문항 최초 비교의 오류 기록은 그대로 유지한다.

`src/compare_rag.py`는 위 고정 질문 5개를 실행한다. 기본 실행은 API 없는 로컬 근거 점검이며, `--generate`를 지정하면 같은 설정 모델의 검색 없는 답변과 기존 RAG 생성 노드의 답변을 만든다. 질문·제공 근거·양쪽 답변·인용 ID 검사·단계별 시간을 JSON에 중간 저장한다. 기존 결과 파일은 덮어쓰지 않는다.

```powershell
python src/compare_rag.py --output outputs/rag_preflight.json
## GMS 생성 최대 10회 사용. 의미 검색 비교는 --mode vector 추가.
python src/compare_rag.py --generate --output outputs/rag_comparison.json
```

최초 일반 실행의 생성 재시도는 `APIConnectionError`로 종료됐다. 이후 네트워크 권한을 적용한 실행에서는 5개 질문의 양쪽 답변을 저장했다. `outputs/`의 원본 중 검토한 비교 JSON을 `docs/evidence/`에 보존했다. 단계별 호출 시간은 NF2001의 첫 질문/후속 질문 UI 측정을 대신하지 않는다.

## 제한

- 비교 전에 고정한 질문 5개만 사용한다. 질문과 판정 기준을 답변을 본 뒤 바꾸지 않는다.
- 기준 답변은 같은 모델이 검색 없이 생성한다. 따라서 일반 모델의 사전 지식이 들어갈 수 있고, 외부 문헌 사실의 검증을 대신하지 않는다.
- RAG 답변은 현재 승인·색인된 8개 발췌 범위에 한정한다. 결과를 전체 화학 지식이나 전체 화합물로 일반화하지 않는다.
- 각 답변의 주요 사실을 원문과 대조한 뒤에만 정확성·인용 점수를 기록한다.
- 검색 없는 답변과 RAG 답변의 시스템 지침은 서로 다르다. 이번 비교는 서비스 동작 사례이며 검색만의 순수 효과를 분리하는 통제 실험은 아니다.
- 질문에 “승인된 발췌”, “원문”처럼 특정 자료를 요구하는 표현이 있어 검색 없는 답변에 불리하다. 일반 화학 지식의 정답률이나 향상률을 주장하지 않는다.
