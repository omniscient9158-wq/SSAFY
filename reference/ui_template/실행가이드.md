# Movie Lab 실행 가이드

압축본을 받아 **로컬 PC에서 테스트로 실행**하는 방법입니다.

전체 흐름은 다음과 같고, 처음 한 번은 20~30분쯤 걸립니다. 대부분 패키지 설치와 위키 색인 시간입니다.

```
1. 준비 (Python·가상환경·.env)  →  2. 색인 만들기  →  3. 색인 검증  →  4. 앱 실행  →  5. 기능 확인
```

> ⚠️ **3단계(색인 검증)를 건너뛰지 마세요.** 위키 색인이 비어 있거나 손상돼도 앱은 오류 없이 뜨고,
> 사실 확인 질문에 전부 "문서로 확인 불가"로 답합니다. 겉으로는 모델 문제처럼 보입니다.

---

## 0. 압축본 구성

```
MovieLab/
├─ README.md                     프로젝트 소개·동작 원리·설정·웹 API 형식
├─ 실행가이드.md                  이 문서
├─ src/
│  ├─ requirements.txt           패키지 (동작 확인한 버전으로 고정)
│  ├─ .env.example               환경 변수 견본 → src/.env 로 복사해 사용
│  ├─ app.py                     Streamlit 화면
│  ├─ server.py · web/           HTML·CSS·JavaScript 화면 + 웹 API        (심화 F2013)
│  ├─ collect_wikidata.py 등     위키데이터 수집·색인                      (심화 F2016)
│  └─ compare_rag.py             RAG 사용 전후 답변 비교                   (심화 F2015)
├─ data/
│  └─ movies.json                영화 메타데이터 964편 (RAG 1 원본)
└─ resources/rag/
   ├─ wiki_manifest.json         영화별 위키백과 문서 목록
   ├─ wikipedia/*.json           위키백과 원문 3,763개 (RAG 2 원본, 약 57MB)
   ├─ wikidata_manifest.json     위키데이터 수집 기록
   └─ wikidata/*.json            위키데이터 원문 (대표 영화 6편)
```

**들어 있지 않은 것**

| 항목         | 이유                                                                             |
| ------------ | -------------------------------------------------------------------------------- |
| `src/.env` | API 키가 들어 있다.`.env.example`을 복사해 직접 만든다                         |
| 벡터 색인    | 약 660MB. 원문에서 다시 만든다(2단계). OS·경로에 묶이지 않게 하려는 목적도 있다 |
| `.venv/`   | OS·Python 버전에 묶인다. 각자 만든다                                            |

## 1. 준비

### 1-1. 필요한 것

| 항목       | 내용                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| Python     | **3.12** (3.12.7에서 확인)                                                             |
| GMS API 키 | https://gms.ssafy.io/web/ 에서 발급. LLM·임베딩 호출에 사용                                 |
| 디스크     | 색인 약 700MB + 패키지 약 1GB                                                                |
| 네트워크   | `gms.ssafy.io`(필수), `ko.wikipedia.org`·`www.wikidata.org`(새 문서를 추가로 받을 때) |

### 1-2. 압축 해제 위치

**영문 경로에 푸는 것을 권장합니다.** (예: `C:\dev\MovieLab`)
한글이 섞인 경로(예: `C:\Users\홍길동\문서\...`)에 풀었다면 1-4의 `INDEX_DIR`을 반드시 영문 경로로 지정합니다.

### 1-3. 가상환경과 패키지

압축을 푼 `MovieLab/` 폴더에서 실행합니다.

```bash
python -m venv .venv

source .venv/Scripts/activate    # Windows (Git Bash)
# source .venv/bin/activate      # macOS / Linux

pip install -r src/requirements.txt
```

> 이후 모든 명령은 가상환경이 활성화된 터미널(프롬프트 앞에 `(.venv)` 표시)에서 실행합니다.
> 새 터미널을 열었다면 `source` 명령을 다시 실행합니다.

### 1-4. 환경 변수 파일 `src/.env`

`src/.env`를 열어 값을 채웁니다. 항목별 설명은 파일 안의 주석에 있습니다.

| 항목             | 필수 여부      | 값                                                                                          |
| ---------------- | -------------- | ------------------------------------------------------------------------------------------- |
| `GMS_KEY`      | **필수** | 발급받은 GMS 키                                                                             |
| `INDEX_DIR`    | **권장** | 색인을 둘**영문 경로**. 예) `C:\movielab_indexes`                                   |
| `CHAT_MODEL`   | 권장           | `gpt-5.4` (견본 기본값). 비우면 `gpt-5.4-nano`로 바뀌고, 사실 판정이 크게 보수적이 된다 |
| `WIKI_CONTACT` | 권장           | 이메일 또는 URL. 비우면 위키백과·위키데이터 요청이 분당 10회로 제한된다                    |

**`INDEX_DIR`이 중요한 이유** — Windows에서 chromadb는 한글이 들어간 경로에 벡터 파일을 쓰지 못합니다.
색인 명령은 성공한 것처럼 끝나지만 검색할 때 `Error loading hnsw index`가 나고, 앱에서는 모든 사실 질문이
"문서로 확인 불가"로 나옵니다. 한글 폴더가 들어간 경우에 작성합니다.

## 2. 색인 만들기 (최초 1회)

**앱을 끈 상태에서** 순서대로 실행합니다. 세 명령 모두 위키 API와 LLM은 부르지 않고 **임베딩 비용만** 발생합니다.

```bash
python src/index_movies.py                 # ① 영화 메타데이터 964건        · 1분 내외
python src/repair_wiki_index.py --apply    # ② 위키백과 원문 → 약 3.6만 청크  · 5~10분
python src/collect_wikidata.py --reindex   # ③ 위키데이터 원문 → 청크 (F2016) · 수 초
```

| 명령                                | 만드는 컬렉션      | 참고                                                                                                                                           |
| ----------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| ①`index_movies.py`               | `movie_meta`     | 영화 1편 = 청크 1개                                                                                                                            |
| ②`repair_wiki_index.py --apply`  | `movie_wiki`     | 중간에 끊기면`INDEX_DIR/movie_wiki` 폴더를 지우고 처음부터 다시 실행한다. 청크가 일부만 들어간 문서는 "이미 있음"으로 보고 건너뛰기 때문이다 |
| ③`collect_wikidata.py --reindex` | `movie_wikidata` | 대표 영화 6편 분량. 나머지 영화는 질문할 때 그 영화만 자동으로 받는다                                                                          |

## 3. 색인 검증 (필수)

```bash
python src/collect_wikidata.py --reindex 
python src/debug_search.py 282631 "명량해전에서 조선 수군 배는 몇 척이었나"
```

| 확인 항목                        | 정상                                                | 비정상일 때                                                                       |
| -------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------- |
| `repair_wiki_index.py` 출력    | `현재 색인: 약 36,000청크` · `유실 0쌍`        | 유실이 있으면 2단계 ②를 다시 실행                                                |
| `debug_search.py` 출력         | 위키 청크 목록에`명량 해전`, `이순신` 등이 보임 | `Error loading hnsw index` → `INDEX_DIR`을 영문 경로로 바꾸고 2단계부터 다시 |
| `INDEX_DIR/movie_wiki/<폴더>/` | `data_level0.bin` 등 `.bin` 파일 4개            | `index_metadata.pickle`만 있으면 경로 문제                                      |

## 4. 앱 실행

화면이 두 가지입니다. **한 번에 하나만** 띄웁니다. 둘은 같은 색인을 쓰므로 동시에 띄우면 색인이 손상될 수 있습니다.

|      | (가) Streamlit 화면                    | (나) HTML·CSS·JavaScript 화면 (심화 F2013)                         |
| ---- | -------------------------------------- | -------------------------------------------------------------------- |
| 실행 | `python -m streamlit run src/app.py` | `python src/server.py`                                             |
| 주소 | http://localhost:8501                  | http://localhost:8000                                                |
| 특징 | 필수 기능 기준 화면                    | 화면(`src/web/`)과 서버(웹 API)가 분리됨. API 문서는 `/api/docs` |

- Streamlit은 첫 실행 때 이메일을 묻습니다. Enter로 넘어가면 됩니다.
- 웹 화면은 `http://localhost:8000/?movie=282631`처럼 영화 ID를 붙이면 그 영화의 대화가 바로 열립니다.
  대화 기록은 브라우저에 저장되어 새로고침해도 남습니다.
- 종료는 터미널에서 `Ctrl + C`.

## 5. 기능 확인

### 5-1. 기본 동작 (두 화면 공통)

사이드바에서 영화를 고르고 채팅으로 질문합니다.

| 영화       | 질문                                                       | 기대 결과                             |
| ---------- | ---------------------------------------------------------- | ------------------------------------- |
| 남한산성   | 영화처럼 인조가 남한산성에서 나와 청에 항복한 게 사실이야? | 답변 끝에`판정: 사실`               |
| 서울의 봄  | 영화의 배경인 12·12 군사반란은 실제로 있었던 사건이야?    | `판정: 사실`                        |
| 택시운전사 | 실제 택시기사 이름도 영화처럼 김만섭이었어?                | `판정: 각색됨` (실존 인물은 김사복) |
| 인터스텔라 | 감독이 누구야?                                             | 판정 줄 없이 한두 문장으로 답         |

**가장 중요한 확인 기준은 답변 아래 근거 목록에 위키백과 문서가 보이는가입니다.**
영화 메타데이터만 보이면 색인 문제입니다(3단계). 응답은 문항당 약 3~12초 걸리고, 처음 묻는 키워드면 문서를 추가로 받느라 더 걸립니다.

> 판정은 LLM이 내리므로 같은 질문도 실행마다 달라질 수 있습니다. 문서에 직접 적혀 있지 않은
> 세부 장면(예: 명량의 백성 구출 장면)은 `각색됨`과 `문서로 확인 불가` 사이를 오갑니다.

같은 화면에서 필수 기능도 확인할 수 있습니다.

| 기능                     | 확인 방법                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 조건 기반 탐색 (F2011)   | 사이드바`🔎 이런 영화 찾아줘`에 "우주 배경에 가족이 나오는 감동적인 영화" → 추천 카드 → 카드를 누르면 그 영화의 대화로 이동 |
| 도메인 특화 기능 (F2010) | 영화를 고른 뒤`📝 리뷰 생성` → 관람 가이드와 근거 목록                                                                       |
| 영화별 대화 (F2009)      | 다른 영화로 바꿨다가 돌아오면 이전 대화가 그 영화에만 남아 있음                                                                 |

### 5-2. 심화 기능

| 과제                                 | 확인 방법                                                                                      | 기대 결과                                                                                          |
| ------------------------------------ | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| **F2013** 프론트엔드 직접 구현 | (나) 웹 화면을 띄우고 5-1의 질문을 한다                                                        | 진행 상태("문서 확인 중 → 답변 생성 중") 표시 후 답변과 근거 목록.`/api/docs`에서 API 형식 확인 |
| **F2014** MMR 검색             | `src/.env`에 `USE_MMR=0`을 넣고 앱을 다시 띄워 같은 질문 → 원래대로 돌려 비교             | 근거 목록의 문서 구성이 달라진다                                                                   |
| **F2015** RAG 전후 비교        | `python src/compare_rag.py --only 3,5`                                                       | `outputs/rag_compare/compare_<날짜시각>.md`에 두 방식의 답이 나란히 저장된다                     |
| **F2016** 여러 문서 출처 결합  | 인터스텔라에서 "아카데미 시상식에서 어떤 상을 받았어?", 명량에서 "전 세계 흥행 수입은 얼마야?" | 근거 목록에`위키데이터` 출처가 표시되고 답에 그 값이 인용된다                                    |

### 5-3. 웹 화면(F2013) 로컬 테스트

심화 기능을 (나) 웹 화면에서 확인하는 순서입니다. Streamlit이 떠 있으면 먼저 끕니다(4단계 참고).

**① 서버 띄우기** — 터미널 1

```bash
source .venv/Scripts/activate      # macOS / Linux: source .venv/bin/activate
python src/server.py               # http://127.0.0.1:8000 , 다른 포트는 --port 8080
```

`Uvicorn running on http://127.0.0.1:8000`이 보이면 준비된 것입니다. 이 터미널은 서버 로그용으로 그대로 둡니다.

**② API 동작 확인** — 터미널 2 (가상환경 활성화 불필요)

```bash
# 서버 상태: 색인 건수·API 키·모델
curl -s http://127.0.0.1:8000/api/status

# 영화 목록 / 영화 상세 (명량 = 282631)
curl -s http://127.0.0.1:8000/api/movies | head -c 300; echo
curl -s http://127.0.0.1:8000/api/movies/282631

# 질의응답 (화면과 같은 순서: 문서 수집 → 답변)
curl -s -X POST http://127.0.0.1:8000/api/movies/282631/collect \
  -H "Content-Type: application/json" \
  -d '{"question": "명량해전에서 조선 수군 배는 몇 척이었나"}'
curl -s -X POST http://127.0.0.1:8000/api/ask \
  -H "Content-Type: application/json" \
  -d '{"movie_id": "282631", "question": "명량해전에서 조선 수군 배는 몇 척이었나"}'

# 조건 기반 탐색 / 리뷰 생성
curl -s -X POST http://127.0.0.1:8000/api/recommend \
  -H "Content-Type: application/json" \
  -d '{"query": "우주 배경에 가족이 나오는 감동적인 영화"}'
curl -s -X POST http://127.0.0.1:8000/api/movies/282631/review
```

| 요청                   | 정상                                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------------- |
| `/api/status`        | `"api_key": true`, `indexes`의 `movie_meta`≈964 · `wikipedia`≈36,000 · `wikidata` > 0 |
| `/api/movies/282631` | `wiki_titles`에 위키 문서 제목 목록, `similar`에 비슷한 영화                                    |
| `/api/ask`           | `answer`(끝에 `판정: …`)와 `sources`(`source_label`에 위키백과가 포함)                     |
| `/api/recommend`     | `results`에 영화 목록과 `reason`                                                                |

오류 처리도 확인합니다. 내부 정보(경로·키·오류 추적)가 응답에 나오지 않아야 합니다.

```bash
curl -s -w " [%{http_code}]\n" http://127.0.0.1:8000/api/movies/0000000          # 404 · 영화를 찾을 수 없습니다.
curl -s -w " [%{http_code}]\n" -X POST http://127.0.0.1:8000/api/ask \
  -H "Content-Type: application/json" -d '{"movie_id": "282631", "question": ""}'  # 422 · 입력값을 확인해 주세요.
```

API 형식 전체는 브라우저에서 http://127.0.0.1:8000/api/docs 를 열면 보이고, 각 API를 `Try it out`으로 직접 호출할 수 있습니다.

**③ 화면 확인** — 브라우저에서 http://127.0.0.1:8000

| 확인 항목        | 방법                                                                      | 기대 결과                                                                                   |
| ---------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 색인 상태 표시   | 첫 화면 사이드바 아래                                                     | `색인: 영화 964건 · 위키백과 …청크 · 위키데이터 …청크 (모델 gpt-5.4)`. 경고 박스 없음 |
| 영화 선택        | 사이드바 입력란에 "명량" 입력 → 목록에서 선택                            | 감독·출연·수집된 위키 문서 목록, 비슷한 영화 버튼                                         |
| 질문과 진행 상태 | 5-1의 질문 입력                                                           | "문서를 확인하고 있습니다…" → "…답변을 만드는 중…" 순서로 바뀐 뒤 답변과 근거 목록      |
| 대화 유지        | 새로고침(F5), 또는 다른 영화로 갔다가 돌아오기                            | 영화별 대화가 그대로 남음 (브라우저`localStorage`에 저장)                                 |
| 주소로 바로 열기 | http://127.0.0.1:8000/?movie=282631                                       | 명량 대화가 바로 열림                                                                       |
| 조건 기반 탐색   | `🔎 이런 영화 찾아줘`에 조건 입력 → 카드의 `이 영화에 대해 질문하기` | 추천 카드 표시 후 그 영화 대화로 이동                                                       |
| 리뷰 생성        | 영화 선택 후`📝 리뷰 생성`                                              | 관람 가이드와 근거 목록                                                                     |
| F2014 MMR        | `src/.env`에 `USE_MMR=0` → 서버 재시작(Ctrl+C 후 ①) → 같은 질문    | 근거 목록 구성이 달라짐. 확인 후`USE_MMR=1`로 되돌림                                      |
| F2016 위키데이터 | 인터스텔라 "아카데미 시상식에서 어떤 상을 받았어?"                        | 근거 목록에`위키데이터` 출처                                                              |

- 대화 기록을 비우려면 사이드바 `이 영화의 대화 지우기`를 누르거나, 브라우저 개발자 도구(F12) → Application → Local Storage에서 `movielab.histories`를 지웁니다.
- 화면에 "요청을 처리하지 못했습니다"가 나오면 터미널 1의 `[오류]` 줄을 봅니다(6단계).
- `.env`나 `src/` 코드를 바꾼 뒤에는 서버를 재시작해야 반영됩니다. `src/web/`의 HTML·CSS·JS만 바꿨다면 브라우저 새로고침(Ctrl+F5)으로 충분합니다.

## 6. 문제 해결

| 증상                                                             | 원인                                              | 조치                                                                 |
| ---------------------------------------------------------------- | ------------------------------------------------- | -------------------------------------------------------------------- |
| 사실 질문이 대부분 "문서로 확인 불가"                            | 위키 색인이 비었거나 손상됨                       | 3단계 검증 → 이상하면 2단계                                         |
| 색인은 정상인데 "확인 불가"가 많음                               | `CHAT_MODEL`이 작은 모델                        | `CHAT_MODEL=gpt-5.4` (README "모델과 답변 품질")                   |
| `Error loading hnsw index`                                     | 한글 경로에 색인                                  | `INDEX_DIR`을 영문 경로로 → 2단계                                 |
| `GMS_KEY가 없습니다` / 웹 화면 상단 경고                       | `src/.env`가 없거나 키가 비어 있음              | 1-4단계                                                              |
| `Could not connect to tenant default_tenant`                   | 여러 프로세스가 색인을 동시에 염                  | 앱과 다른 스크립트를 모두 끄고 하나씩 실행                           |
| 웹 화면에 "요청을 처리하지 못했습니다"                           | 서버 내부 오류 (상세는 서버 터미널 로그에만 남음) | `server.py`를 띄운 터미널의 `[오류]` 줄 확인                     |
| 포트가 이미 사용 중                                              | 8501·8000을 다른 프로그램이 씀                   | `streamlit run ... --server.port 8502` / `server.py --port 8080` |
| `[경고] WIKI_CONTACT가 비어 있어…` / `[429] …초 후 재시도` | 위키미디어 요청 제한                              | 동작에는 문제없다. 느리면`WIKI_CONTACT` 설정                       |
| `[검색 실패]` / `[수집 중단] 위키백과 연결이 불안정합니다…`     | 일시적인 네트워크 오류                            | 동작에는 문제없다. 실패한 검색어는 이력에 남지 않아 다음 질문에서 다시 수집한다 |

### 처음부터 수집해 쓰고 싶을 때

위키백과 원문 없이 질문 시점에 수집하게 하려면 매니페스트를 치워야 합니다. 매니페스트에 "수집 완료"로 적힌 영화는
수집을 건너뛰므로, 원문 없이 두면 위키 근거가 영원히 비게 됩니다.

```bash
mv resources/rag/wiki_manifest.json resources/rag/wiki_manifest.prebuilt.json
```

이 경우 영화마다 첫 질문에 1~2분이 걸리고, LLM(키워드 추출·문서 선별)과 위키 API를 호출합니다.
(위키데이터는 매니페스트가 있어도 색인·원문이 없으면 자동으로 다시 받으므로 따로 할 일이 없습니다.)
